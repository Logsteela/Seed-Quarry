# 再開用メモ（2026-09-05）

## 起動

通常は既存の Rebuild and Run ショートカット、またはルートの
`rebuild-and-run.ps1` を使う。ビルド先は
`build-dev-debug/debug/seed-atlas.exe`。Qt DLLと構造物manifestはexeの隣に必要。

## 現在の重点

Java 1.16.1が最優先。GUIでは1.16を選んで村の1.16.1計算を使う。
1.16.5そのものの完全再現や1.20以降は後回し。

村・砦の配置、チェスト座標、Loot条件は実装済み。ただし砦のバージョン判定は
内部1.16.1限定で、通常GUIの1.16選択ではまだ利用できない。
村の木・pile・サボテン等は一部配置状況で共有RNGを確定できずUNKNOWNになる。
UNKNOWNを一致や不一致と捏造しない。

村Loot高速化ON + family blocksでは、1workerに1つの48-bit familyを渡す。
村Loot以外が通ったSeedを調べ、Lootが確定不一致ならfamilyの残りを省略する。
意図的な非網羅検索であり、全探索するには高速化OFFを使う。
Loot一致時は通常の結果処理へ進み、UNKNOWNではfamilyを打ち切らない。

今回、NOT・ORゲート・Lua・村Lootの除外条件を含む検索では、この省略を
無効化するガードを追加した。Lootを一時的に外すとNOT等の意味が変わり、
本来合格のSeedを評価せず飛ばしていたため。アイテム欄のAND/ORは併用可能。

## 次の候補

1. 同じ64-bit Seed・村座標・biomeの配置と生Loot結果を、複数のLoot条件で再利用。
   上位16bitを跨がないキャッシュなら厳密性を維持できる。メモリ上限も必要。
2. 残る木・pile・サボテンのUNKNOWNケースを少数のoracleで検証。
3. 砦をGUIの1.16から使うためのバージョン対応整理と回帰テスト。
4. 村の48-bit onlyへのLoot事前判定。現在は村Lootの絞り込みをせず候補を残す。

完成した水平Jigsawを同一48-bit familyへ無条件に流用してはいけない。
地形高度が3D衝突判定を変え、XZのpiece列まで変わる。
既存の平坦高度近似は一致率が低く、厳密検索の棄却条件には使えない。

## 軽い検証

`dev-build.ps1 -NoRun -SkipTests` で本体をビルドした後、
`test-loot.ps1 -SkipAppBuild` でLoot単体・検索統合テストを実行。
NOTの回帰セッションは最後の上位16bitだけを調べるため、全65536Seedを
計算せずにGUIの1.16指定も含めて検証できる。

コンパイルは1並列。大量のJavaチャンク生成や重いベンチマークは避ける。
`genBiomes` の作業領域は単純な面積分では足りない場合があり、`allocCache`を使う。
既存のLICENSE差分と、外側の作業フォルダーにある別件の画像処理ファイルは触らない。
